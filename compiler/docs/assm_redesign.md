# ASSM 模块重构计划

## 当前问题诊断

### 1. **值跟踪系统混乱** ❌
- `allocator.get_value_id()` 每次调用都生成新 ID，导致同一个 LLVM Value 被分配多个不同的寄存器
- `alloca` 指令的结果（栈地址）没有被正确记录和查找

### 2. **Alloca 指令处理错误** ❌  
当前实现：
```rust
// 错误：计算栈地址，但没有保存指令本身的映射
add w0, sp, #4
```

正确应该：
```rust
// Alloca 不生成代码，只记录栈偏移
// 栈地址在使用时(load/store)才计算
```

### 3. **Store 指令处理错误** ❌
当前输出：
```asm
str w1, [w1]  # 错误：地址寄存器和值寄存器相同
```

正确应该：
```asm
mov w8, #5       # 加载立即数到临时寄存器
str w8, [sp, #4] # 直接存储到栈地址
```

### 4. **Load 指令处理错误** ❌
需要根据 alloca 记录的栈偏移来加载值

## 修复方案

### 方案 1：简单栈式分配（推荐先实现）
- **所有变量存储在栈上**
- **临时值使用固定的几个工作寄存器** (w8, w9, w10...)
- **不做复杂的寄存器分配**

优点：
- 简单，易于实现和调试
- 100% 正确性
  
缺点：
- 性能较差（大量 ldr/str）

### 方案 2：改进的寄存器分配（后续优化）
- 使用活跃区间分析
- 实现线性扫描寄存器分配
- 溢出时才使用栈
